> **The Heart to Heart Constitution**
>
> This document sits above every other document in this project.
> It is the supreme law of the product.
> Every feature, every design decision, every line of code is measured against it.
> If a decision conflicts with this Constitution, the Constitution wins.

---

## Preamble

Heart to Heart exists for one purpose: **to help two people draw closer to Jehovah — and to each other — through meaningful, guided Bible discussion.**

Every document in this project serves this purpose. Every feature serves this purpose. Every pixel, every sound, every word serves this purpose.

When we are unsure about a decision, we return to this Constitution. If a feature does not align with it, the feature does not get built.

---

## The Principles

### Principle 1 — Technology Serves Worship

> **Technology serves worship. Never the other way around.**

The app is a tool, not the experience. The technology should disappear into the background, allowing the worship to take center stage. If a technical feature distracts from worship, it is wrong — no matter how impressive it is.

**Test:** Does this technology make worship easier, deeper, or more beautiful? Or does it make the app more impressive?

---

### Principle 2 — Beauty Invites Reflection

> **Beauty should invite reflection, not distract from it.**

The app should be beautiful — warm, peaceful, storybook-like. But beauty is a doorway, not a destination. The visuals should draw the user into reflection, never pull them away from it. If an animation is flashy but shallow, it fails. If a design is simple but invites stillness, it succeeds.

**Test:** Does this visual element make the user more contemplative, or more entertained?

---

### Principle 3 — The Bible Remains Central

> **The Bible remains central. The application guides conversations. It never replaces Bible reading.**

The app is a guide, never a substitute. Users are always encouraged to open their own Bibles or JW Library. Scripture is always presented accurately (NWT) with references. The app never claims to replace personal Bible reading, prayer, or the guidance of the congregation.

**Test:** Does this feature encourage the user to open their Bible, or does it replace that need?

---

### Principle 4 — Discussion Is More Valuable Than Completion

> **Discussion is more valuable than completion. Users should never feel rushed.**

There are no timers. No scores. No "progress bars" that pressure. A session that ends mid-way but produced a deep conversation is more successful than a session that was "completed" quickly. The app should feel unhurried, like a quiet evening — not a checklist.

**Test:** Does this feature pressure the user to move faster, or does it invite them to linger?

---

### Principle 5 — Every Feature Must Answer the Question

> **Every new feature must answer: "Will this help two people draw closer to Jehovah?"**

This is the ultimate test. When considering any new feature, animation, sound, screen, or content, ask this question. If the answer is not a confident "yes," the feature does not get built.

**Test:** Will this help two people draw closer to Jehovah?

---

## The Guardrails

### Never Do These

- ❌ **Never add competition.** No scores, no timers, no winners, no losers, no leaderboards, no streaks.
- ❌ **Never add pressure.** No "you missed a day," no "50% complete," no urgency.
- ❌ **Never replace Bible reading.** The app guides; it never substitutes.
- ❌ **Never use flashing or jarring animations.** Peace is the aesthetic.
- ❌ **Never add popups or interruptions** that break the flow of worship.
- ❌ **Never add ads, tracking, or analytics** without explicit approval.
- ❌ **Never invent scriptures or misquote scripture.** Accuracy is sacred.
- ❌ **Never make the app about the app.** It is about the worship.

### Always Do These

- ✅ **Always encourage conversation.** Every feature leads to dialogue.
- ✅ **Always prefer beauty over complexity.** Simple and beautiful beats clever and complex.
- ✅ **Always keep the spiritual focus.** Every screen points to Jehovah.
- ✅ **Always use warm, gentle language.** Like a kind friend, not a teacher.
- ✅ **Always respect the user's pace.** Nothing auto-advances.
- ✅ **Always ask before changing the architecture.** The engine is sacred.

---

## The Decision Framework

When evaluating any new feature or change, run it through this framework:

```
1. Does it serve worship?          (Principle 1)
2. Does it invite reflection?      (Principle 2)
3. Does it keep the Bible central? (Principle 3)
4. Does it value discussion?       (Principle 4)
5. Does it draw two people closer to Jehovah? (Principle 5)

If ANY answer is "no" → the feature does not get built.
If ALL answers are "yes" → the feature may proceed.
```
